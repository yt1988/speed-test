直接接続ルール：プロキシではなく自分の回線を測る

プロキシを使っていると、テストもプロキシを通るので、プロキシのノードの速度を測ることになります。このルールを入れると、テストで使うドメインだけが直接接続になり、ほかの通信はそのままです。

プロキシの設定を再読み込みしてから、もう一度測ってください。プロキシのノードの速度を測りたいときは、このルールを入れないでください。

ヘルプ

どうやって測っているのですか？

ブラウザが Cloudflare の速度テストサーバー（speed.cloudflare.com と同じもの）に直接つながります。接続先はお使いの回線から最寄りの Cloudflare データセンターで、データはこのサイトを通りません。

まず小さなリクエストを 16 回送り、遅延とジッターを測ります。次に下りです。複数のリクエストを同時に流し、届いたデータをその場で数えながら 5〜10 秒測ります。最初の 30% は接続が加速している途中なので除き、その後の平均を速度とします。速度が安定したら早めに終わります。上りも同じ方法で測ります。下りと上りの間は 0.15 秒ごとに小さなリクエストを送り、回線がいっぱいのときの遅延を測ります。

契約速度やほかのテストより遅いのはなぜ？

いちばん多い原因は Wi-Fi です。回線そのものの速度を知りたいときは、ルーターに有線でつなぎ、ほかの端末の通信を止めてから測ってください。

もう一つは測り方の違いです。ブラウザとテストサーバーの間は接続 1 本（HTTP/2 または HTTP/3 を複数のリクエストで共有）ですが、Ookla の Speedtest アプリは接続をたくさん開きます。サーバーが近ければ結果はほぼ同じですが、遠いほど接続 1 本では不利になります。また Ookla はプロバイダーの網内にあるサーバーで測ることが多く、網の外へ出る経路より良い数字が出がちです。

中国本土では Cloudflare のデータセンターが国外にあるため、国際回線の帯域を測ることになり、契約速度を大きく下回ることがあります。

Bufferbloat とは？ 評価はどう決まるのですか？

Bufferbloat（バッファーブロート）は、回線が混んだとたんに遅延が跳ね上がる現象です。家族が大きなファイルをダウンロードしたり高画質の動画を見たりした途端、ゲームやビデオ通話が重くなるなら、たいていこれが原因です。

原因はルーターやモデムにあります。回線がいっぱいになると、データを大きなバッファーにためて順番待ちさせるため、ゲームのデータや通話の音声がダウンロードの後ろで待たされます。

テストでは、まず回線が空いているときの遅延を測り、ダウンロード中とアップロード中は 0.15 秒ごとに測って、それぞれ中央値を出します。空いているときより何 ms 増えたか（下りと上りの悪いほう）で評価が決まります。しきい値は Waveform の Bufferbloat テストと同じで、5 ms 未満 A+、30 ms 未満 A、60 ms 未満 B、200 ms 未満 C、400 ms 未満 D、それ以上 F です。

改善するには：C 以下なら、ルーターで SQM（スマートキュー管理。fq_codel か CAKE）を有効にすると、ほとんど解決します。代わりに最高速度が少し下がります。この機能の名前はルーターによって異なり、SQM、Smart Queue、QoS などと呼ばれます。ない場合は、OpenWrt を入れるか、対応したルーターに替えるのが近道です。

遅延（Ping）とジッターはどう測るのですか？

「開始」を押すだけで、インストールは要りません。結果には、空いているとき、ダウンロード中、アップロード中の 3 つの遅延が出て、それぞれにジッターが付きます。

遅延は、データがサーバーまで往復するのにかかる時間です。空いているときの遅延は、主に Cloudflare までの距離と経路の質で決まります。ジッターは遅延が 1 回ごとにどれだけ揺れるかで、大きいと通話が途切れ、ゲームがカクつきます。ダウンロード中・アップロード中に遅延がどれだけ増えるかが、Bufferbloat の評価になります。

ビデオ通話やゲームの前に測ると、回線が持ちこたえられるかがよく分かります。

4K 動画やゲームは快適にできますか？ どう判定していますか？

テストが終わると、5 つの用途を「快適」「まあまあ」「厳しい」で判定します。基準は一般的な目安で、サービスによって必要な条件は少しずつ違います。

4K 動画：下り 25 Mbps 以上で快適。5 Mbps 以上でまあまあ（HD なら問題なし、4K は読み込みで止まることがあります）。

ビデオ通話：下り・上りとも 3 Mbps 以上、遅延 80 ms 以内、ジッター 20 ms 以内で快適。下り 1.5 Mbps・上り 1 Mbps、遅延 200 ms、ジッター 50 ms まででまあまあ。

オンラインゲーム：遅延 40 ms 以内、ジッター 10 ms 以内、回線がいっぱいのときの増加 30 ms 以内で快適。それぞれ 100、30、100 ms まででまあまあ。

クラウドゲーム：下り 35 Mbps 以上、遅延 40 ms 以内、ジッター 10 ms 以内で快適。15 Mbps、80 ms、20 ms まででまあまあ。

ライブ配信：上り 20 Mbps 以上で快適、5 Mbps 以上でまあまあ。

どれにも届かなければ「厳しい」です。ゲームが重いときは、遅延・ジッター・Bufferbloat が原因のことが多いので、まず有線接続を、次にルーターの SQM を試してください。動画や配信が止まるときは、たいてい帯域が足りていません。

プロキシや VPN を使っているときは、誰の速度ですか？

プロキシの速度です。プロキシや VPN がオンだと、ブラウザはそれを経由してテストサーバーにつながります。速度は 3 つの区間（あなたからプロキシのノードまで、ノード自体の帯域、ノードから Cloudflare まで）のうち、いちばん遅いところで決まります。ノードを比べるには便利です。

自分の回線を測るには、直接接続ルール（プログレスバーの横のボタン）を追加してください。speed.cloudflare.com だけが直接接続になり、ほかの通信は変わりません。Clash/Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray に対応し、多くは自動で最新に保たれるルールセットで使えます。

見出しの下に出る出口（都市、ネットワーク、IP）を見れば、テストがどの経路を通ったか分かります。プロキシらしいときは、ページがお知らせします。

1 回のテストで通信量はどれくらい？

各方向とも、速度が安定すれば 5 秒、長くても 10 秒で終わります。つまり下り・上りそれぞれ、最高速度で 5〜10 秒分です。100 Mbps の回線なら合計で約 100〜250 MB、1 Gbps なら 1〜2.5 GB です。テストのあと、使った通信量を表示します。モバイル回線やデータ量に上限のあるプランでは、回数を控えめにしてください。

なぜ自動で始まらないのですか？

速度テストは通信量が多いので、「開始」を押すまで待つようにしています。よく測るなら、プログレスバーの横にある「ページを開いたら自動で測る」をオンにしてください。この設定はこのブラウザにだけ保存されます。

UDP のパケットロスと QUIC の欄は何？

通話やゲーム、ライブ配信は UDP でデータを送ります。失われたパケットは再送されません。テスト中、ページは UDP（WebRTC）で毎秒 50 個の小さなパケットを東京のサーバーへ送り、戻ってこなかった数を数えます。回線が空いているとき、下り中、上り中のそれぞれです。1% 未満なら問題なし。数 % になると通話が途切れ、ゲームがカクつきます。

QUIC（HTTP/3）も UDP を使います。会社や学校、国際回線の一部は UDP を遮断・制限し、アプリは TCP に戻ります。QUIC の欄は通るかどうかを示し、同じサーバーへの TCP と往復時間を比べます。Safari はこの判定に必要な WebTransport に対応していないため「判定不可」と表示されます。

サーバーは東京だけです。日本から遠いほど、ロスやジッターの一部は東京までの長い経路によるもので、あなたの回線だけのものではありません。2 つ合わせて約 0.5 MB です。

データは集めていますか？

このサイトはテスト結果を集めていません。テストはブラウザと Cloudflare のサーバーの間で直接行われ、結果はこのサイトに届きません。「問題を報告」を選んだときだけ、今回の結果が私たちに送られます。どのサイトとも同じく、Cloudflare にはあなたの IP アドレスが見えます。UDP と QUIC の判定では、東京にある当サイトのサーバー（rtc.1ms.dog）に接続します。テスト中は IP アドレスが見えますが、パケットを数えるだけで、ログも含め何も残しません。

履歴はお使いのブラウザにだけ保存されます。共有リンクと画像もブラウザの中で作られ、含まれるのは数値と日時だけです。国と Cloudflare のデータセンターを入れるかどうかは選べます。IP アドレスが入ることはありません。コードは GitHub で公開しています。
