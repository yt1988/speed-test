直接接続ルール：プロキシではなく自分の回線を測る

プロキシ使用中はテストがプロキシ経由になり、プロキシの経路とノードを測ることになります。このルールはテストのホストだけを直接接続にします。

プロキシの設定を再読み込みして、もう一度測定してください。プロキシノードの速度を測りたいときは、ルールを入れないでください。

ヘルプ

どうやって測っているの？

ブラウザが Cloudflare の速度テストサーバー（speed.cloudflare.com と同じもの）に直接つながります。接続先はあなたの回線から最寄りの Cloudflare データセンターで、このサイトは経由しません。

まず空のリクエスト 16 回で Ping とジッターを測ります。次に下り：複数のリクエストを同時に流し、届いたバイトをその場で数えて 5〜10 秒測定。速度は最初の 30% を除いた（接続が加速しきった後の）平均で、速度が安定したら早めに終わります。上りも同じように逆方向で測ります。どちらの間も 0.4 秒ごとに小さなリクエストを送り、回線がいっぱいのときの Ping を測ります。

契約速度や他の速度テストより遅いのはなぜ？

いちばん多い原因は Wi-Fi です。回線そのものの速度を見るには、有線でつなぎ、ほかの端末の通信を止めて測ってください。

ブラウザとテストサーバーの間は HTTP/2 または HTTP/3 の接続 1 本（複数のリクエストで共有）ですが、Ookla のアプリは独立した接続をたくさん開きます。近いデータセンターなら結果はほぼ同じですが、遠いほど 1 本の接続は不利になります。また Ookla はプロバイダー網内のサーバーで測ることが多く、網外へ出る経路より良い数字が出ます。

中国本土では Cloudflare のデータセンターが国外にあるため、国際回線の帯域を測ることになり、契約速度を大きく下回ることがあります。

負荷時の Ping（バッファーブロート）とは？

回線がいっぱいになると、ルーターやモデムはパケットを大きなバッファーにためます。ダウンロードの後ろに並んだゲームのパケットや通話の音声はすべて待たされます。これがバッファーブロートです。

このテストは下りと上りの最中に Ping を測ります。増加が 30 ms までなら問題なし。100 ms を超えると、誰かが写真をアップロードしたりバックアップが走ったりするたびに通話やゲームで体感できます。ルーターのスマートキュー管理（SQM：fq_codel や CAKE）でほとんど解消でき、代わりに最高速度が少し下がります。

プロキシや VPN を使っているとき、誰の速度？

プロキシの速度です。プロキシや VPN がオンだとブラウザはそれを通ってテストサーバーにつながるので、数値はあなたからプロキシノードまでの回線、ノード自身の帯域、ノードから Cloudflare までの経路を表します。ノードの比較には便利です。

自分の回線を測るには、直接接続ルール（プログレスバー横のボタン）を追加してください。speed.cloudflare.com だけが直接接続になり、ほかは変わりません。Clash/Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray に対応し、多くは自動更新されるルールセットで使えます。見出しの下に出る出口（都市、ネットワーク、IP）でテストがどの経路を通ったか分かり、プロキシらしいときはページが知らせます。

1 回のテストで通信量はどれくらい？

各方向は速度が安定すれば 5 秒、長くても 10 秒で終わるので、上り下りそれぞれ最高速度で 5〜10 秒分です。100 Mbps の回線なら合計約 100〜250 MB、1 Gbps なら 1〜2.5 GB。テスト後に使った量を表示します。従量制やモバイル回線では控えめに。

なぜ自動で始まらないの？

速度テストは通信量が多いので、「開始」を押すまで待ちます。よく測るなら、プログレスバー横の「ページを開いたら自動で測定」をオンにしてください。この設定はこのブラウザに保存されます。

データを集めていますか？

いいえ。テストはブラウザと Cloudflare のサーバーの間で行われ、このサイトは結果を受け取りません。どのサイトとも同じく、Cloudflare にはあなたの IP アドレスが見えます。共有リンクと画像はブラウザ内で作られ、数値だけを含みます。コードは GitHub で公開しています。
